# 故障演练：Redis 不可用时的降级与熔断

日期：2026-11-11
演练人：本人
场景：缓存节点（Redis）完全不可用

## 一、演练目的

验证「缓存单点」对系统的影响，并检验降级方案是否有效。

## 二、演练步骤

```bash
docker stop redis                       # 制造故障
ab -n 20000 -c 200 -k http://127.0.0.1:8080/   # 压测观察
docker start redis                      # 恢复
```

## 三、故障现象（修复前）

| 指标 | 数值 |
|---|---|
| 页面状态 | `失败：php_network_getaddresses: getaddrinfo for redis failed`（HTTP 仍为 200） |
| 单请求耗时 | 首次 0.09s，压测中 P95 达 **5172 ms** |
| QPS | **20.37**（正常 1700） |
| MySQL CPU | 0.02 核（**完全没有被访问**） |

**三个问题：**

1. **服务完全不可用**：Redis 挂 = 功能挂，没有降级。
2. **每请求阻塞约 5 秒**：容器停止后 Docker DNS 不再解析 `redis`，PHP 的 `connect timeout` 管不了 DNS 解析阶段。
3. **HTTP 200 掩盖故障**：状态码正常，监控与告警都无法发现。

## 四、根因

- 代码中 `new Redis()` 失败直接抛出异常，没有回退逻辑；
- 无熔断机制，每个请求都重复尝试连接失败的服务；
- 监控端点 `/metrics.php` 同样依赖 Redis，导致**故障时监控也失效**（Prometheus 抓取超时，target 变 DOWN）。

## 五、修复方案

### 5.1 降级

Redis 不可用时，直接查询 MySQL，保证页面可用：

```
请求 → 尝试 Redis
        ├─ 命中 → 返回
        └─ 失败/未命中 → 查 MySQL →（Redis 可用时）写回缓存
```

### 5.2 熔断

失败后写入 `/tmp/redis_down_until`，30 秒内不再尝试 Redis，避免每个请求都付出 DNS 超时成本。

```php
$downUntil = (int)@file_get_contents('/tmp/redis_down_until');
if (time() >= $downUntil) {
    try { $redis->connect('redis', 6379, 0.2); ... }
    catch (Throwable $e) { @file_put_contents('/tmp/redis_down_until', time() + 30); }
}
```

### 5.3 监控解耦

`/metrics.php` 改为读取本地文件计数器，不再依赖 Redis，保证故障期间监控仍可用。

## 六、复验结果（修复后）

| 场景 | 页面状态 | 耗时 | QPS | MySQL CPU |
|---|---|---|---|---|
| Redis 正常 | 缓存命中（Redis） | 0.009 s | ~1700 | 0.025 核 |
| Redis 挂 · 首次 | 缓存不可用，已降级直查 MySQL | 0.102 s | — | — |
| Redis 挂 · 后续 | 缓存不可用，已降级直查 MySQL | **0.009 s** | **857** | **0.156 核** |
| 恢复后 | 回源查询并写回缓存 | 0.011 s | — | — |

**结论：**

- 服务由「完全不可用」变为「可用但吞吐下降约 50%」（1700 → 857）；
- 熔断使重复请求从 5 秒降到 9 毫秒；
- 数据库压力上升约 6 倍，但未被打满；
- Redis 恢复后 30 秒内自动回补缓存，无需人工干预。

## 七、结论与可迁移经验

1. **缓存是加速手段，不能成为唯一路径**：任何缓存都必须有回退到数据源的路径。
2. **超时要覆盖全链路**：`connect timeout` 不覆盖 DNS 解析，失败时可能阻塞远超预期。
3. **熔断比重试更重要**：对已经确定不可用的依赖，立即失败好过反复等待。
4. **监控不能依赖被监控的服务**：观测端点若依赖业务依赖，故障时会同时失效。
5. **HTTP 200 不代表健康**：应用层错误要用业务指标（如 `app_cache_up`、错误日志）暴露，不能只看状态码。

## 八、遗留问题

- MySQL 仍是单实例，降级后所有流量压到单库，容量有限；
- 未实现限流，数据库被打满时没有保护；
- 缓存写回失败时无补偿机制。
